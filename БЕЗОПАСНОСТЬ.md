# Безопасность

## Границы доверия

- `Telegram -> backend`: `POST /telegram/webhook` с `X-Telegram-Bot-Api-Secret-Token`.
- `Manual/cron -> backend`: `POST /jobs/*` с `X-Webhook-Secret`.
- `backend -> Telegram Bot API`: исходящие сообщения только через `TelegramClient`.
- `backend -> parser API`: только по `PARSER_API_URL` + Bearer `PARSER_API_TOKEN`.

## Базовые требования

1. Все секреты только в `.env`/secret manager, не в коде.
2. Порты `5432/8000/5678` не публиковать наружу напрямую.
3. Использовать reverse proxy и rate limits (`deploy/nginx.conf.example`).
4. Для webhook включен constant-time compare (`hmac.compare_digest`).
5. Ограничение размера body и in-memory rate limiting включены в приложении.

## Правила логирования

- Запрещено логировать токены, пароли, webhook secrets.
- Запрещено логировать исходные payload целиком.
- Допустимо логировать только технические идентификаторы (`request_id`, `supplier_id`) и `error_type`.

## SQL и данные

- Схема меняется только через Alembic миграции.
- Для `quotes` действует уникальность `(request_id, supplier_id)`.
- Для hot-path добавлены индексы (`requests`, `quotes`, `messages_out`, `raw_prices`, `parsed_items`).

## Обработка сообщений

- Команды сотрудников обрабатываются только в разрешенной группе или в личке владельца заявки.
- Поставщик не может привязать reply к чужой заявке (проверка отправленного `MessageOut`).
- Для денег используются `Decimal`, не `float`.
