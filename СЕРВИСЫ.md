### LLM в Coolify (backend `bot-saller`)

Код принимает **только** эти значения `LLM_PROVIDER` (регистр не важен): `openai` | `openai_compatible` | `openrouter` | `ollama`.

`LLM_PROVIDER=deepseek` **не работает** → `unsupported_llm_provider:deepseek`.  
`LLM_PROVIDER_NAME=DeepSeek` — это подпись в billing-напоминании, **не** роутинг API.

DeepSeek — OpenAI-compatible ([документация](https://api-docs.deepseek.com)): клиент бьёт `{LLM_BASE_URL}/chat/completions`.

```env
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
LLM_API_KEY=<ключ из Coolify, не в git>
LLM_TIMEOUT_SECONDS=30
```

Если `LLM_BASE_URL` оставить дефолт `https://api.openai.com/v1`, ключ DeepSeek уйдёт на OpenAI и получит 401.

После сохранения env в Coolify: **Restart** (или Redeploy) `bot-saller`. Settings читаются один раз при старте (`get_settings` + lru_cache).

Проверка LLM снаружи невозможна. Внутренне: Coolify logs после первого разбора ответа поставщика / `POST /jobs/morning-price` с `X-Webhook-Secret` — не должно быть `llm_provider_not_configured` / `unsupported_llm_provider` / `llm_api_key_or_model_missing`.

### Что осталось для полной эксплуатации

1. Сверить LLM-переменные с контрактом выше + Restart backend.
2. `/menu` → сотрудники; поставщики.
3. Userbot в канале прайса → `/menu` → канал `supplier_price_source` → `pending → active`.
4. Supabase: `suppliers.price_channel_id` + `price_channel_username`; активные `markup_rules` (хотя бы `*`).
5. `PRICE_APPROVAL_CHAT_IDS` (чаты approve) **плюс** все `owners.dm_ok=true` получают черновик прайса в ЛС. Заместитель `260271772` — owner; после `/start` draft приходит без правки Coolify. `PRICE_PUBLISH_CHAT_IDS` — куда публиковать после approve.
6. Ручной `POST /jobs/morning-price` → `degraded=0`, затем cron **11:00 MSK** (окно каналов 08:00–11:00).

Вне MVP: Ollama/`ai_process` в parser, S3, публичный URL parser API.

## tg-channel-parser в Coolify

### Тип ресурса

- **Docker Compose** (Service Stack)
- **Base directory:** `tg-channel-parser/`
- **Compose file:** `docker-compose.tg-parser.yml`
- **Domains:** не назначать (API и Postgres закрыты)
- **Connect to Predefined Network:** Coolify → parser → **Advanced → Docker compose → Predefined network → Connect to predefined network** (не Isolated). У `bot-saller` (Dockerfile) отдельного тумблера нет: сеть destination уже `coolify` (General → Internal access → Docker network). После смены у parser — **Redeploy**, иначе контейнеры не присоединятся.

### Сервисы в stack

| Сервис | Назначение |
|---|---|
| `tg-parser-postgres` | PostgreSQL 15, volume `tg_parser_pg_data` |
| `tg-parser-migrate` | one-shot `alembic upgrade head` |
| `tg-listener` | Pyrogram realtime |
| `tg-worker` | resolve_channel + download_media |
| `tg-parser-api` | FastAPI :8000 internal |

Host ports **не** пробрасываются (убраны `127.0.0.1:8081` и `5433`).

### Env parser (Coolify UI, секреты не в git)

```env
POSTGRES_USER=tg_parser
POSTGRES_PASSWORD=<сгенерировать>
POSTGRES_DB=tg_parser
DATABASE_URL=postgresql+asyncpg://tg_parser:<ПАРОЛЬ>@tg-parser-postgres:5432/tg_parser

TELEGRAM_API_ID=<my.telegram.org>
TELEGRAM_API_HASH=<my.telegram.org>
TELEGRAM_SESSION_STRING=<после auth_cli, только Coolify>

API_AUTH_TOKEN=<сгенерировать, совпадает с PARSER_API_TOKEN backend>

MEDIA_STORAGE_BACKEND=local

```

### Telegram: три разных секрета (не путать)

| Что | Откуда | Куда |
|---|---|---|
| Bot token | @BotFather | backend `TELEGRAM_BOT_TOKEN` |
| `api_id` + `api_hash` | https://my.telegram.org/apps (1 номер = 1 приложение) | parser `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` |
| `TELEGRAM_SESSION_STRING` | `auth_cli` после кода/2FA | parser Coolify env |

Из РФ `my.telegram.org` часто падает без VPN. VPN лучше в стране номера (+7 → RU); инкогнито без расширений; если приложение уже создано — смотреть `/apps`, не плодить второе.

Env **Coolify UI ≠** `~/BOT_SALLER/tg-channel-parser/.env` на диске VPS. CLI читает только локальный `.env`.

### MTProto auth (один раз, интерактивно)

Compose требует `${TELEGRAM_SESSION_STRING:?required}` **до** запуска `auth_cli` (пустая строка = ошибка interpolating). Chicken-and-egg:

```bash
cd ~/BOT_SALLER/tg-channel-parser
test -f .env || cp .env.example .env
# заполнить TELEGRAM_API_ID/HASH, DATABASE_URL, API_AUTH_TOKEN, POSTGRES_PASSWORD (непустые)
# заглушка обязательна — иначе compose не стартует:
# TELEGRAM_SESSION_STRING=placeholder
docker compose -f docker-compose.tg-parser.yml run --rm -it --no-deps \
  tg-listener python -m app.mtproto.auth_cli
```

`--no-deps` — не поднимать postgres/migrate ради логина. Вывод (длинная строка) → `.env` на VPS **и** Coolify parser env → Deploy. В чат не копировать.

Не коммитить `.env` / `*.session`.

### Сеть backend ↔ parser (Coolify v4)

При **Connect to Predefined Network** internal DNS по имени сервиса (`tg-parser-api`) **не резолвится** между разными Coolify-ресурсами. Нужен **hostname контейнера** `tg-parser-api` (часто короткий Docker ID, пример после redeploy 2026-09-06: `697c288c6249`).

**Hostname меняется при каждом Redeploy parser.** После редеплоя заново `docker inspect` и обновить `PARSER_API_URL` у bot-saller.

```bash
docker inspect -f '{{.Config.Hostname}} {{range $k,$v := .NetworkSettings.Networks}}{{$k}} {{end}}' \
  $(docker ps --filter name=tg-parser-api --format '{{.ID}}')
```

Ожидание: две сети — `coolify` и `ssnr4auxpbo6jccgixbbmppd`. Первое поле = hostname.

```env
PARSER_API_URL=http://<hostname>:8000
PARSER_API_TOKEN=<тот же что API_AUTH_TOKEN>
PARSER_TIMEOUT_SECONDS=15
```

Скрипт `smoke-from-backend.sh` в образе backend **обычно нет** (Dockerfile копирует только `backend/`). Smoke из контейнера bot-saller:

```bash
docker exec -it <backend> bash -lc '
  curl -sf "$PARSER_API_URL/health"; echo
  curl -s -o /dev/null -w "noauth:%{http_code}\n" "$PARSER_API_URL/channels"
  curl -sf -H "Authorization: Bearer $PARSER_API_TOKEN" "$PARSER_API_URL/channels"; echo
'
```

Успех 2026-09-06: `{"status":"ok","db":"ok"}`, `noauth:401`, `[]`.

## API контракт parser

- `GET /health` — без auth, `{"status":"ok","db":"ok|error"}`
- `GET /channels` — Bearer, JSON-массив
- `POST /channels` — `{"handle":"@channel","purpose":"supplier_price_source"}` → 202, `status: pending`
- `DELETE /channels/{id}` — деактивация (`id` = PK в `parser_channels`, не Telegram id)
- `GET /posts?channel_id=&content_type=text&from=&limit=&cursor=` → `{"items":[...],"next_cursor":...}`

Backend `parser_client` принимает и legacy-массив, и paginated envelope; сам обходит все страницы.

## Операционный порядок (первый запуск)

1. Deploy parser stack, дождаться `tg-parser-migrate` success
2. `GET /health` parser → `db: ok`
3. Predefined network + UUID-hostname
4. Backend `PARSER_*` + restart
5. `/menu` → **Сотрудники** (добавить менеджера: имя + Telegram ID из @userinfobot или forward)
6. `/menu` → **Поставщики** → **➕ Добавить поставщика** → ввести имя → привязать ЛС одним из способов:
   - **Переслать сообщение** — переслать боту сообщение от поставщика;
   - **Ссылка** — отправить поставщику ссылку `https://t.me/<bot>?start=<token>` (TTL 24 ч);
   - **Пропустить** — работа только через групповой чат (добавить бота в группу → «Новые чаты» → «Поставщик»).
   Сменить/отвязать ЛС можно в карточке поставщика. Технарь не лезет в SQL.
7. `/menu` → добавить канал `supplier_price_source`
8. Дождаться `pending → active` (worker resolve)
9. `/menu` → карточка поставщика → **Канал прайса** (или fallback SQL: `suppliers.price_channel_id = <telegram channel_id>`)
10. Ручной `POST /jobs/morning-price` → `degraded=0`
11. Только потом полагаться на APScheduler 11:00 MSK

Скрипты: `tg-channel-parser/scripts/coolify-bootstrap.sh`, `smoke-from-backend.sh`, `trigger-morning-price.sh`.

### Миграции parser (prod volume)

Первый успешный `0002` на пустом volume: `alembic_version` = `0002_channel_resolution` после migrate exit 0. Том `ssnr4auxpbo6jccgixbbmppd_tg-parser-pg-data` **не удалять** без бэкапа.

Исправления `0002` в git (`606d9ab`, `83d4bca`), иначе migrate падает:

- нельзя `DROP UNIQUE parser_channels.channel_id` — на нём FK `parser_posts`; UNIQUE уже допускает несколько NULL;
- нельзя в той же транзакции, что `ALTER TYPE ... ADD VALUE 'resolve_channel'`, создать индекс `WHERE task_type = 'resolve_channel'` (`UnsafeNewEnumValueUsageError`). Индекс без predicate.

Логи причины — `docker logs` контейнера `tg-parser-migrate-…`, не сводка Coolify.
